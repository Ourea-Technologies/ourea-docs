Most weather APIs make you sign up before your first request. Ourea doesn't:
the forecast, current-conditions and alert routes for named locations answer
requests with **no credentials at all**, and search and the catalog need none.

## What works without a key

| Works anonymously | Needs a Pro key |
|---|---|
| Forecast for a named location (`/api/v1/locations/{state}/{slug}`), to 240 h | Forecast at coordinates (`/api/v1/forecast`) |
| `prob=` probabilities and `totals=` window totals | `models=true`, `run=` |
| Plumes (`members=true`, plume view) | Every member variable in plumes |
| `/current` and `/alerts` for a named location | `/current` and `/alerts` at coordinates |
| Search, nearby (by location and by coordinate), catalog, runs, storm reports, attribution | |

## Why anonymous is fast

An anonymous request to a canonical URL can be answered by the edge cache:
every caller asking for the same place shares one cached body. Keyed requests
are `private` and always reach the server. So for public, named-location data,
not sending a key is often the better choice. See
[Caching and ETags](/features/caching/).

<Aside>
Anonymous requests are budgeted per client address. If many users share one
address (a server, a NAT), give that server a key so it has its own budget.
</Aside>

## When to add a key

- You need your own rate budget rather than your network's.
- You need Pro: coordinates, 15 days, per-model data, historical runs.

Self-serve keys open at launch: you'll create one from your account (see
[Get an API key](/getting-started/#get-an-api-key)). A wrong key
is `401 INVALID_API_KEY`, not a quiet fall-back to anonymous; to go anonymous,
send no key.
